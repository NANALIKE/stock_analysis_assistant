# BaoStock 全市场历史日行情采集：设计与开发计划

实施备注（2026-11-24）：已批准进入开发。SDK 实际日 K 合同为 18 个字段，
下文“19”是原计划计数错误，实施保留全部字段。下文探索表描述开发前状态；
最终实现与验证结果见 `docs/development/baostock-collection.md` 和
`docs/development/baostock-acceptance.md`。

## 一、目标与已确认范围

接通现有 Go 服务和 Python Worker，实现真实的 BaoStock 数据采集、标准化、
可恢复历史补采、质量校验、原子发布及已发布行情查询。

本次已确认：

- 全市场指 BaoStock 可获取的全部沪深 A 股，包含历史退市股；北交所列为来源覆盖缺口，不接入其他来源。
- 实现现有 `backfill` 与 `daily` 两种请求；`daily` 为手工触发，不建设自动调度器。
- 完成开发、离线验收和真实在线抽样，提供从 2000 年起的全市场全量入口；本次不启动或等待整个全历史任务完成。
- 沿用一期完整日行情模型：19 个日 K 字段、四项估值、逐日状态、三个因子、分红送转与不可变原始响应。
- 保持 Go 唯一业务编排者和 SQLite 写入者、非常驻 Python Worker、本地单用户及现有 5 个 REST 路由。
- `none/qfq` 都保存，查询默认 qfq；前复权只调整 OHLC，前收参考价、来源涨跌幅、量额、估值、状态不复权。

不包含前端、预测/回测、财报/新闻、收费源、分钟行情、自动定时调度及多进程并发采集。

## 三、执行方案与接口决定

### 3.1 分批采集与数据流

流程固定为：
`领取任务 → 固定目标/父版本 → 主数据与日历 → 历史日期证券集合与日线 →
缺口修复 → 完整因子/分红 → qfq → 质量报告 → 原子发布`。

1. 主数据拉取全部证券原文，按 `type=1`、交易所与 A 股代码规则筛选。
   SH 接受 600/601/603/605/688/689，SZ 接受 000/001/002/003/300/301；
   未识别代码不凭前缀强行纳入，登记排除/待核查明细。
   证券 ID 固定由规范化交易所/代码生成，主数据刷新不改变身份。
2. 从 2000 年起的日期和上市/退市区间构建应有集合。
   历史 `query_all_stock(day)` 与主数据取并集发现遗漏证券，对未知历史代码调用
   `query_stock_basic(code=...)` 补齐；不只使用今天的在市股票。
   退市日是否含最后交易必须由历史日线/当日集合证据确认；冲突日期登记问题。
3. 全市场补采优先按交易日调用 `query_all_stock` 与
   `query_daily_history_k_AStock`。单日批次含全部 19 字段、adjustflag=3；
   指定股票只保留目标标准化事实，但全量原始响应完整保存。
4. SDK 接口缺失，或日批次字段/口径契约不满足时，切到单股/年份
   `query_history_k_data_plus` 策略；非零来源错误先按重试规则处理，不用空数据替代。
   部分股票请求直接采用单股/年份策略，避免无必要的全市场请求。
5. 对缺失证券日调用单股区间接口修复；无明确停牌证据仍为 missing。
   两次来源响应冲突保留双方并登记问题，不能覆盖后就宣称无冲突。
6. 默认一次 Worker 只处理一个日市场批次；小型因子/分红调用最多合并 8 个查询，
   保持最大输出 64 MiB，不把全市场多年代输出装进一个进程批次。
   超限批次拆小后重试；单股年份超限再按季度、月递归拆分到单日，仍超限则明确失败。
7. 每次执行器只并行 1 个 Worker、SDK 会话内串行查询。
   请求间默认间隔 0.2 秒，每个来源查询最多 3 次，退避为 1 秒、3 秒；
   参数非法/字段契约错误不盲目重试。重试等待支持取消。
   Worker 默认 5 分钟超时作用于一个批次，整项历史任务没有 5 分钟总时限。
8. 日历、当日清单和全部分页遍历都要检查完整结束；
   交易日全市场空行情不能标为完成。成功空因子/分红可以完成，需保存请求范围和零记录证据。

历史补采必须显式给出截止日期，不晚于最近已收盘交易日。
通过上海时间和来源日历在异步任务内校验；已收盘但来源未更新时明确失败/待重试。
未来/尚未收盘日期在进入来源采集前拒绝，不为解析默认日期阻塞 POST 的 202 响应。

### 3.2 Worker 契约与原始制品

保持信封 `schema_version=1` 和 `operation=collect/protocol_check`；
collect 的 params 新增受校验的 `queries` 列表，query 含 `query_id`、
operation 和精确参数，只允许计划中的 BaoStock 查询，不执行任意方法名。

每个 `record.data` 为一个 `source_response`，包含：
`query_id/operation/request/fields/rows/fetched_at/provider_published_at/
error_code/error_message/complete`。
`rows` 为按字段顺序的 SDK 原字符串数组；空值、未知字段和错误响应均原样保留。
另附 `records` 归一化结果和 `issues` 逐行问题列表，用于日线/主数据/日历/状态/因子/分红转换；
必填记录非法时保留原文并登记问题，不能把整批原始记录丢掉。

正常来源失败在合法响应记录中表达；进程/连接异常导致未拿到完整响应时，
Go 记录失败 provider_call，整份无 end/哈希错误的批次不得导入。
Python 在 finally 登出，导入/调用 SDK 的 stdout 始终重定向 stderr。
`protocol_check` 继续无需 SDK、无需网络。

Go 先验证信封，再把每个查询的完整响应单独压缩到 raw 内容寻址仓库。
在同一短事务中登记 artifact、snapshot、provider_call 结果与完成检查点；
标准化写入失败不把单元标为已完成。文件已落地但事务失败产生的未引用原文可复用，
本次不增加制品清理器。snapshot 来源发布时间在 SDK 未提供时保持 NULL。

### 3.3 因子、分红与前复权

- 每只目标股从上市日显式拉取完整因子至逻辑 as_of，保留三个十进制因子。
  成功空集合对应无事件，不能由接口错误推断无事件。
- 分红按上市年份至目标年份查询 `operate/report` 两种口径并持久化每次响应；
  去重哈希基于原始字段内容，不包含查询年份/口径。
  已存在的完整响应检查点可续用；同日多方案和修订不能合并成一条。
- qfq 使用供应商完整、正值累计后复权因子：
  `qfq(t) = none(t) × B(t) / B(anchor)`；
  B(t) 取不晚于 t 的最新 backAdjustFactor，上市后首事件前 B=1，
  空因子集合 B=1。anchor 为逻辑版本 as_of。由 Go 领域层用 `math/big.Rat`
  对源十进制因子做精确有理数运算，最终 ROUND_HALF_UP 到 1/10000 元，
  检查 int64 范围，保留精确算法版本和全部输入哈希；不把历史日线再传回 Worker 重算。
- 此公式必须先由真实无事件、首事件前后、多事件与历史锚点样本核验，
  并检查来源累计因子与除权参考价的关系；不直接照搬示例的 fore 前填 1。
  对供应商 `adjustflag=2` 返回序列，按同一股票的参考日价格比例归一到本地锚点再比较，
  防止供应商当前锚点与历史 as_of 不同造成误判。
- 比较容差包括 0.0001 元舍入，以及返回因子各自十进制精度的传播误差：
  以每个因子末位的半单位误差做区间运算，计算价格界限；差异超过这个界限即失败，
  不放宽为任意百分比。完整保存差异明细。
- 如果累计因子语义核验失败，采集结果、原始因子和问题报告仍保留，
  任务以复权校验失败结束，不发布 qfq、不偷换为供应商黑盒结果；记录明确的未通过项。
- `daily` 中新股或新事件先拉该股完整因子；对已有目标股也刷新完整因子以检测历史修订。
  完整集合或算法/相对锚点变化，重算该股受影响全部历史年份。
  分红在 daily 刷新当年及上一年的两种口径，并对因子事件涉及的历史年份补查；
  重跑 backfill 可触发完整历史分红刷新，不建设另一个调度器。

### 3.4 版本继承、续采与发布

新版本继承父版本全部分区和因子集合清单；变化的股票/年份整体构建，
同时复制旧 none/qfq、估值及状态，再合并新记录。状态独有年份也登记分区。
补采早年不倒退活动 as_of；首次补采 as_of 取请求最后交易日，
后续取父版本 as_of 与本次截止交易日的较大值。
首次空库小范围或 daily 只发布其实际覆盖范围，报告明确非全市场/非完整历史，
不得把任务范围外的缺数包装成全部 A 股 99.5%。

增加 `dataset_instrument_ranges`：逻辑版本＋证券＋区间起点为主键，
保存实际声明覆盖的 from/to 区间；重叠/相邻区间合并，不把未请求的中间缺口填进覆盖范围。
继承时同时继承这些区间，部分股票早年补采只扩展目标股票的区间。
状态报告给出 selection_scope、区间是否全证券一致及覆盖证券数；
单股查询给出该股声明覆盖区间，避免用一个全局最早日期冒充全市场历史。
全市场任务仍以完整主数据/历史集合为分母，不能靠缩小区间或证券集合通过门禁。

若已有版本包含请求目标以外的证券，部分股票请求的截止不得晚于父 as_of，
否则异步任务以 INVALID_ARGUMENT 失败，提示使用全市场 daily/backfill 推进截止日。
这样不把尚未刷新因子的其他股票绑定到新的全局锚点。
首次选股版本或覆盖其全部证券的请求可以推进 as_of；推进时刷新全逻辑证券集合因子。

增加持久化采集上下文与查询单元：

- `generation_contexts`：job_id、冻结父版本、as_of、市场/日期/证券范围、
  主数据和日历快照、计划版本、范围与输入哈希。
- `generation_units`：job_id＋稳定 query_key 唯一、查询类型/参数、单元状态、
  已验证 snapshot_id、记录数、校验哈希、错误与时间。
- `generation_unit_attempts`：job_id＋query_key＋执行次序，关联来源调用/任务 attempt，
  记录重试过程。成功空响应也有完成单元。
- `generation_jobs` 增加单元进度列；`processed_records` 表示有效基准证券日，
  不把 none/qfq/估值计成三条行情；新增 completed_units/total_units 单独表达采集进度。

保持幂等默认行为：重复 POST 同一请求返回原任务，queued/running/succeeded 不重复执行。
通过既有 POST 的查询参数 `retry=true` 显式重试 failed；CLI 用 `-retry` 映射此参数。
请求 body 与幂等键不增加 retry 字段，相同 job_id 下递增 attempt。

重启仍将旧 running attempt 明确标为 interrupted/failed，保留完整检查点；
不在启动时无限自动重试。用户重试后重用冻结计划和已验证原文，跳过成功来源查询。
failed 版本拒绝发布；新 attempt 创建新的 building 版本，从已完成原始响应重放
标准化事实，不引用 rejected 物理分区。升级过归一化算法时重做转换，原始查询不重拉。
复权验证失败后的显式重试需刷新因子与核验样本，不重复使用已知错误输入。

发布前一个质量报告覆盖整个逻辑清单：逐日/逐年及整体完整率均统计；
应有证券日中合法日线或有证据的停牌可覆盖，未上市/已退市/休市不在分母内。
每个报告范围内有应有数据的交易日覆盖率必须 ≥99.5%，防止总体掩盖整日缺失。
估值各列非空率单独统计，不因合理空估值拒绝价格。
因子/分红调用缺失、非法价格、状态冲突、未核验复权、半批次和制品/清单引用错误
不得被完整率数字掩盖。未实施分红预案不要求与因子事件逐一匹配。

在单个事务内确认父活动版本仍与构建时一致、质量通过、分区/因子引用有效，
将旧 active 变为 superseded，新 building 变为 active，并同时完成 job/attempt。
父版本变化时拒绝发布并记录冲突；采集和长时间校验不占数据库事务。
来源失败/校验失败保留旧 active 可查询。读取只使用 active 逻辑清单及其
active/superseded 物理块，不读取 building/rejected 数据。

### 3.5 公开接口、CLI 与配置

保持 5 个路由，只扩展：

- POST `/market-data/generations?retry=true`：显式续采；body 原样。
- GET generation：新增 completed_units/total_units 与阶段进度；
  quality 结果包含报告制品引用，原始供应商 stderr 不返回 API。
- GET market-data/status：依据交易日历/已收盘时间判断 stale，
  返回实际覆盖范围 market_scope/selection_scope/from/to/universe_size/ranges_uniform，
  coverage 分母和范围不再只靠一个无说明数值。
- 日线查询字段与默认 qfq 保持兼容，增加该股 coverage_ranges，
  范围外无数据通过状态/范围元数据说明。

`stockctl generate` 增加 `-retry`。
新增 `stockctl backfill [-from 2000-01-01] -to 日期 [-symbols ...] [-retry]`，
由 stockd 接收同一种请求，不离线写库。from 默认 2000-01-01，to 必须显式传入；
API 继续要求 backfill 的 from/to，日期范围与幂等键保持原有含义。
CLI 默认打印 202 与 status_url，不等待全量完成。

配置新增 `market_data.request_interval/max_query_attempts`，固定单 Worker；
保留现有 worker timeout/max_output_bytes。启动检查依赖/协议可用性，
SDK 不可用时生成任务明确 SOURCE_UNAVAILABLE，但已发布查询保持可用。
不添加付费 API Key。安装运行环境使用仓库外独立虚拟环境，通过
STOCK_WORKER_PYTHON 指定解释器，不污染系统 Python。

## 五、验证与验收

### 5.1 离线验证

普通 CI 不依赖 BaoStock 在线服务。新增/更新验证覆盖：

- 完整分页结束、中途 error_code 改变、SDK stdout 污染、空集合与接口缺失、
  19 字段和新增字段、非法必填值、四位量额、负估值、税后多值分红。
- 真实来源固定样本与显式数值边界测试分开；SDK stub 不作为在线准入证据。
- qfq 无事件、首事件前后、多事件、历史锚点、除权日 preclose、
  退市/停牌跨事件、因子修订；量额/估值/来源比例不复权。
- 单日期全市场批次和单股区间 fallback 产生一致事实；64 MiB 限制下拆分与取消。
- 重复请求、显式重试同 ID、重启 interrupted、检查点跳过已完成网络调用、
  原文损坏后重拉、同一事务内导入/检查点提交和断点崩溃恢复。
- 单日更新不丢同年历史；跨年、部分股票更新、状态独有块、
  qfq 因子变化重算历史与旧 active 继续可读；
  非连续区间不宣称连续完整、部分股票不能不刷新其他证券就推进全局锚点。
- 非法来源/缺失/停牌冲突的分母、逐日和逐年完整率、合理估值 NULL。
- 发布事务回滚、父活动版本冲突、rejected 无法引用为发布事实、
  DB/制品一致性和历史清单传递引用。
- 空库小范围发布明确范围、未来/未收盘日期、必填截止日期、
  非交易日 stale、默认 qfq、显式 none 和现有 5 个 API 的兼容。
- 从 v1/v2 升级到 003，重复迁移无变化，旧行情/金额单位保留，外键/完整性通过。

运行 `make check`（Go/Python 测试、vet、ruff、OpenAPI、diff check）及
`make build`；新文件另外检查格式与文档链接，不能仅依赖 git diff 检查未跟踪文件。

### 5.2 真实在线抽样

在仓库外隔离运行环境安装锁定 SDK，以限制范围的真实请求采集：

1. 元数据、日历、一个全市场历史交易日，验证批量字段、证券类型过滤、逐日覆盖。
2. 按真实主数据选择至少三只包含老股/较新股/退市股的证券，
   对老股至少验证 2000 年起的一小段与多个真实除权事件窗口。
   无事件、停牌/ST 案例从真实返回中选取，不伪造线上案例。
3. 完整因子和选定历史年度 `operate/report` 分红，验证事件、空值和多方案。
4. 本地 qfq 与归一锚点的供应商 qfq 对比；实际响应、字段/来源版本和差异报告留存。
5. 在独立测试库完成真实抽样 backfill 发布，再手工 daily/同年修复，
   查询 none/qfq 与估值/状态；中断后显式重试验证不重复下载成功批次。

验收报告区分：已通过离线项、已通过在线项、未验证场景、来源缺口；
不以一个成功交易日宣称 2000 年以来全市场完整或 18:00 SLA 达标。
来源无法连接时仍完成离线开发，报告准确写明在线验收未通过；
不得以 mock 代替并宣称整项验收通过。

### 5.3 数据库升级与交付

- 先验证现有 backup 清单，再备份数据库/raw/artifacts，应用 003 并运行 doctor、
  `PRAGMA integrity_check/foreign_key_check`；不删除旧数据或旧迁移。
- 在线验收数据置于明确的抽样运行目录，最终可查询演示数据与证据归档到配置 var 目录；
  一次性调试脚本/环境/缓存保持仓库外。
- 最终交付可执行采集链路、完整设计/操作文档、离线与在线抽样报告、
  全量 backfill 和失败续采命令。
- 本次不提交 Git、不启动全市场多年代任务、不建设自动调度。
