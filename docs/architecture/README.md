# 架构设计

本目录保存股票分析助手的架构决策与阶段性边界，作为产品、研发和验收的共同基线。

## 文档清单

| 文档 | 状态 | 用途 |
|---|---|---|
| [产品架构](product-architecture.md) | 终版 | 定义 MVP 目标、范围、产品领域、数据闭环、验收门禁、风险与演进路径 |
| [技术架构](technical-architecture.md) | 终版；目录能力 2026-11-25 修订 | 定义技术选型、运行时边界、数据与模型管线、存储/API 契约、目录能力与模块依赖、本地存储配置及 Git 边界、演进门槛 |
| [一期日行情数据模型](market-data-model.md) | 2026-11-24 修订 | BaoStock 全字段与接口映射、精度/空值、逐日状态、因子/分红、增量清单与发布契约 |
| [采集实现](../development/baostock-collection.md) | 已实现 | 查询白名单、检查点、重试、复权与运行环境 |
| [采集验收](../development/baostock-acceptance.md) | 2026-11-24 | 离线测试、真实样本与未验证范围 |

产品架构决定“做什么与为什么”，技术架构决定“如何以当前资源可靠交付”。日行情数据模型细化一期存储与采集契约，三份文档共同作为当前实施基线；实现进度以项目 README 和数据模型的实施状态为准。

各产品能力的业务需求和独立交付变更统一维护在[产品需求目录](../product/README.md)，影响整体范围、数据口径或验收门禁时同步更新本目录的相关架构文档。

## 维护约定

- 架构文档记录已经确认的决策，不以未验证假设替代事实。
- 影响 MVP 范围、数据口径、用户承诺或验收门禁的变更，必须同步更新产品架构。
- 未来能力与当前实现分开描述，避免把预留方向误解为本期交付。
- 新增目录、调整模块职责或改变存储位置约定时，同步维护技术架构第 10 节的目录能力、依赖与配置映射。
- 预测模型、数据源与基础设施选型变化不能破坏可追溯、可重放和可评估的产品原则。
